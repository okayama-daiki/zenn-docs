## はじめに

Overleaf や LaTeX Workshop に代表される高機能なクラウドエディタや便利ツールの普及により、今日では $\LaTeX$ の内部構造を深く意識することなく文書を作成できるようになりました。一方で、この利便性は、$\LaTeX$ を取り巻く用語や概念を体系的に理解する機会を奪いかねません。

その結果としてしばしば見られるのが、とりあえずコンパイルが通るまで設定を総当たりで試すという行動です。例えば、学会や出版社が指定する投稿規程を満たす文書を作成する際に、エンジンやドキュメントクラスを理解しないまま、エディタの設定を片っ端から切り替えてみた経験はないでしょうか。運が良ければ正解に辿り着きますが、そうでなければ理由も分からないままコンパイルエラーに悩まされ続けることになります。これは極めて非生産的な時間の使い方です。

近年ではこうしたトラブルに対し、大規模言語モデル (LLM) から対話的な支援を受けられるようになりました。しかし、エラーメッセージをそのまま貼り付けるだけでは、得られる回答の質にも限界があります。背景となる概念を把握した上でツボを押さえた質問や指示ができるかどうかが、問題解決の効率を大きく左右します。

本エントリでは、「雰囲気でコンパイルする」状態から一歩進むために、$\LaTeX$ を構成する用語や概念を整理し、適切なメンタルモデルを構築することを目的とします。最終的には、手作業でのコンパイル手順を理解し、`latexmk` のような自動化ツールの有用性を実感できることを目指します。

本エントリは、以下のトピックで構成されます。前半では、$\TeX{}$ と $\LaTeX{}$ の違い、$\TeX{}$ エンジンとマクロパッケージの区別、ドキュメントクラスといった要素を取り上げ、$\LaTeX{}$ を構成する概念や用語の整理を行います。後半では、Bib$\TeX{}$ に代表される文献処理ツールの位置付け、$\TeX{}$ ディストリビューションとコンパイルコマンドの関係を確認した上で、手作業によるコンパイル手順を解説します。最後に、これらの手順を自動化するツールとして、`latexmk` が何を肩代わりしているのかを簡単に紹介します。

## $\LaTeX$ の構成要素

### マクロパッケージ：$\TeX$ と $\LaTeX$ を混同しない

> マクロパッケージとは、$\TeX$ の原始命令だけを使って構築された高水準の命令集合です。

$\TeX$ そのものは、`\hbox`, `\vskip`, `\def` のような、極めて低レベルな命令しかもちません。
これを人間が書くのは現実的でないので、よくある組版操作を、意味のある命令としてまとめたものをマクロパッケージと呼びます。$\TeX$ の上に構築されたマクロパッケージの一つが $\LaTeX$ です。
例えば、$\LaTeX$ にあって $\TeX$ にない命令として `\section` や `\begin{...}~\end{...}` があります。これらは内部的には、$\TeX$ のプリミティブ命令に展開されるということですね。

ところで、

> TeX は「テック」または「テフ」([tex])と読みます。 どちらかというと日本の大学関係者の人は「テフ」派が多いようです。 英語圏では [tek]，[tekh] または誤読ですが [teks]，ドイツ語圏では「テヒ」([tɛç]) とも読むようです。 同様に LaTeX は「ラテック」「ラテフ」などと読みます。
>
> TeX の読み方 - TeX Wiki (https://texwiki.texjp.org/?TeX#gea7d22e)

とはありますが、別に友達がラテックスと呼んでても指摘するなんて野暮なこと私はしません。ラテフでもラテックスでも私の頭の中には同じイメージが浮かんでいるので。ええ私ですか？レイテックと呼んでいますよ。きっと伝わらないでしょうが。

### 改めて $\TeX$ とは：言語としての $\TeX$ とエンジンとしての $\TeX$ を区別する

> $\TeX$ を実現するためのコンピュータプログラムがエンジンです。

例えば Python スクリプト（ソースコード）と Python の処理系（CPython, Jython, PyPy）が区別されるように、$\TeX$ においてもこれらの違いについて考える必要があります。

Donald Ervin Knuth が発明した $\TeX$ という言語（あるいは仕様とでも呼ぶべきでしょうか）は、そのままではただの記号の羅列なので、当然これらを解釈し実行するための処理系が必要です。Knuth 本人によって自作された処理系は奇しくも言語と同じ $\TeX$ という名前を持ちますが、他にも例えば、日本語組版をエンジンレベルで扱うために拡張された p$\TeX$ や、p$\TeX$ をさらに多言語に対応するように拡張した up$\TeX$、Unicode を前提とし、さらに Lua 言語による拡張機構を内蔵した Lua$\TeX$ などがあります。

Python の比喩に完全に一致しない部分もあります。Python は言語仕様が明文化されており、基本的にどの処理系もその仕様に従うことが期待されます。私の知る限り、`CPython` で実行できるコード（`python3 xxx.py` のように）は例外こそあれ基本的には `PyPy` でも実行できます（`pypy3 xxx.py`）。

他方で $\TeX$ の世界では、他の $\TeX$ エンジンは（p$\TeX$ や Lua$\TeX$）、オリジナルの $\TeX$ を拡張しているという関係にあることから、エンジン間で振る舞いが異なるというのはあり得る話です。
例えばキリル文字を含んだ .tex ファイルを日本語を前提とした p$\TeX$ で実行しようとしても当然処理できません。up$\TeX$ や Lua$\TeX$ が必要なわけです。

### コンパイラ：Overleaf の設定項目に出てくる、$\LaTeX$ や Lua$\LaTeX$ の正体

次の画像はかの有名な $\LaTeX$ のクラウドエディタ Overleaf の設定画面です。

![](https://storage.googleapis.com/zenn-user-upload/be87b2446ea4-20260118.png)
_Overleaf の設定画面。ポップアップの周囲をポチポチさせしまったら申し訳ありません。_

Chappy 氏曰く「$\LaTeX$ Compiler や $\LaTeX$ Engine というのは標準化された用語ではない」とのことですが、Web 上ではこれらの単語が沢山ヒットするので一定の市民権を得た単語であるのは間違いないでしょう。その真偽はまた後日調査することにして、本エントリ中では $\LaTeX$ Engine を特定の $\TeX$ Engine とマクロパッケージを合わせた概念くらいにぼやかしておきます。

$\TeX$ エンジンについては先ほど述べた通り、言語としての $\TeX$ を処理するプログラムの一つです。これに対して $\LaTeX$ と呼ばれるものは、いくつかの代表的な $\TeX$ エンジンの上に構築された便利なマクロパッケージです。（ただし、全ての $\TeX$ エンジンと互換があるわけではないことに注意してください）。同様にして p$\TeX$ エンジンの上に構築されたマクロパッケージを p$\LaTeX$ といいます。
一方で、Lua$\TeX$ エンジンの上に構築されたマクロパッケージが Lua$\LaTeX$ かというと、**そういうわけではありません！** Lua$\LaTeX$ とは、Lua$\TeX$ エンジン上で $\LaTeX$ を実行する実行形態を指す慣用的な呼称です。

まさに Overleaf の Compiler 設定項目にある Lua$\LaTeX$ オプションは、この実行形態のことを指します。同様に $\LaTeX$ オプションも、マクロパッケージの意味ではなく、特定の $\TeX$ エンジンの上で $\LaTeX$ を実行する形態のことを指しているのでしょう。

#### $\TeX$ エンジンとマクロパッケージの整理

ここで一旦有名な $\TeX$ エンジンをまとめてみます。

| $\TeX$ エンジン | 備考                                                                 |
| --------------- | -------------------------------------------------------------------- |
| (Knuth) $\TeX$  | Knuth によるオリジナル実装。                                         |
| pdf$\TeX$       | $\TeX$ を拡張し PDF を直接出力可能にしたエンジン。長年の標準。       |
| Xe$\TeX$        | Unicode 前提。OS のフォントを直接利用可能（OpenType/TrueType）。     |
| Lua$\TeX$       | Unicode 前提。Lua による拡張機構を内蔵した後継エンジン、最近の標準。 |
| p$\TeX$         | 日本語組版向けに拡張されたエンジン（非 Unicode）。                   |
| up$\TeX$        | p$\TeX$ を Unicode 対応させた日本語組版向けエンジン。                |

よく見る (u)p$\TeX$ という表記は、日本語組版向けのエンジンということでひとまとめにしているということですね。続けて、マクロパッケージは、

| マクロパッケージ | 対応する $\TeX$ エンジン       | 備考                                                                              |
| ---------------- | ------------------------------ | --------------------------------------------------------------------------------- |
| plain $\TeX$     |                                | Knuth が開発した最小限の命令セット。                                              |
| $\LaTeX$         | pdf$\TeX$, Xe$\TeX$, Lua$\TeX$ | 現在最も広く使われている汎用マクロパッケージ。                                    |
| p$\LaTeX$        | p$\TeX$                        | 日本語組版向けに拡張された LaTeX。                                                |
| up$\LaTeX$       | up$\TeX$                       | Unicode 対応の日本語 LaTeX 環境。                                                 |
| Con$\TeX$t       | Lua$\TeX$                      | $\LaTeX$ とは独立。デザインの調整がやりやすいとのことです。おしゃれな名前ですね。 |

のように整理できます。いわゆる pdf$\LaTeX$ というのが pdf$\TeX$ + $\LaTeX$、Xe$\LaTeX$ は Xe$\TeX$ + $\LaTeX$、Lua$\LaTeX$ は Lua$\TeX$ + $\LaTeX$ という対応関係です。

しっかり言葉を整理した上で「レポートを Word ではなく $\TeX$ で書きましょう！」みたいな過去の発言を思い出すと背筋が凍る気持ちです。厳密に区別すると、低レベルな命令セットだけであの美しい文書を再現せよということですから。

もちろん今後同じ言い間違いをしている人を見かけても、指摘なんてしませんよ。

### ドキュメントクラス

$\LaTeX$ の系譜を引くマクロパッケージによって処理される文書に話を限定すると（つまり plain $\TeX$ や Con$\TeX$t を用いる場合は除くと）、多くの場合、.tex ソースの最上部でドキュメントクラスを宣言することにより、文書全体の設計方針や体裁が決定されます。例えば `\documentclass[lualatex, article]{jlreq}` の `jlreq` とか、`\documentclass[aspectratio=169]{beamer}` の `beamer` にあたるものです。

`\documentclass[lualatex, article]{jlreq}` に `lualatex` が含まれているので、これは混乱を招きそうです。これは `\documentclass{jlreq}` 命令のオプションの一つであり、実行時の $\TeX$ エンジンに影響を与えるものではありません。`jlreq` クラスにおける `lualatex` オプションは、単に Lua$\TeX$ 系エンジンで処理されることを想定した場合の内部設定を有効にするためのフラグにすぎません。

#### ドキュメントクラスと TeX エンジンのおおまかな対応関係

| ドキュメントクラス                  | $\TeX$ エンジン                | 備考                                                                                                                       |
| ----------------------------------- | ------------------------------ | -------------------------------------------------------------------------------------------------------------------------- |
| `article` / `report` / `book`       | pdf$\TeX$, Xe$\TeX$, Lua$\TeX$ | 標準的な汎用クラス。世界的な La$\TeX$ 環境では事実上これら3系統が前提。                                                    |
| `beamer`                            | pdf$\TeX$, Xe$\TeX$, Lua$\TeX$ | スライド作成用クラス。                                                                                                     |
| `jlreq`                             | Lua$\TeX$, (u)p$\TeX$          | Requirements for Japanese Text Layout（日本語組版処理の要件）準拠のクラス。article / book の形式はオプションで指定します。 |
| `jarticle` / `jreport` / `jbook`    | p$\TeX$                        | 旧来の日本語 p$\LaTeX$ 環境向けクラス。                                                                                    |
| `jsarticle` / `jsreport` / `jsbook` | (u)p$\TeX$                     | 旧来の日本語 (u)p$\LaTeX$ 環境向けクラス。                                                                                 |
| `jsclasses`[^jsclasses]             | (u)p$\TeX$                     | 上のやつよりはこれ。                                                                                                       |
| `ltjsarticle` など                  | Lua$\TeX$                      | `jsclasses` 互換の Lua$\LaTeX$-ja 専用の日本語クラス。                                                                     |

$\TeX$ エンジンによって使えるコマンドが変わってくるので、任意のドキュメントクラスを任意のエンジンで自由に組み合わせられるわけではなく、両者の間には暗黙の対応関係が存在します。

[^jsclasses]: https://texwiki.texjp.org/?jsclasses

### 文献処理：Bib$\TeX$ とは何か。何を使えばいいのか。

ドキュメントクラスと $\TeX$ エンジン、マクロパッケージ $\LaTeX$ よりも混乱に陥りやすいテーマであることは間違いないですが、良いニュースがあります。
StackExchange で投稿された質問「bibtex vs. biber and biblatex vs. natbib」にて、Alan Munn [^stackexchange] による洗練された素晴らしい回答がありますので、要点を絞ってお伝えします。興味がある方は Alan の回答をご覧ください。

第一に、特に指定しない場合 $\LaTeX$ の文献処理では Bib$\TeX$ を用います。つまり、特段のパッケージの読み込みを行う必要なしに、`\cite` 命令や `\bibliographystyle`、`\bibliography` 命令を使うことができます。（なお、ここで `natbib` パッケージを読み込むことで、より表現力の高い`\citet`, `\citep` 命令を使うことができます。）$\LaTeX$ のコンパイルの手順の中で Bib$\TeX$ を呼び出すことで、.bib ファイルの文献リストが処理されます。その結果 .bst ファイルに従って整形された .bbl ファイルが生成されます。$\LaTeX$ はこの .bbl ファイルを読み込みながら文書全体のコンパイルを進める流れになります。

他方で、`biblatex` パッケージ（Bib$\LaTeX$）を読み込むと、従来 `\cite`、`\bibliographystyle`、`\bibliography` 命令に代表される従来の $\LaTeX$ の文献処理モデルそのものが置き換えられます。従来の文献処理では .bst ファイルを用いて整形を行っていたところを、Bib$\LaTeX$ では全て $\LaTeX$ マクロに置き換えたというのが一番重要な点で、これにより引用スタイルを容易にカスタムすることができます。.bib ファイルの読み取りや文献ソート等といった他の処理は、`biblatex` のオプションとして、Biber または Bib$\TeX$ を指定することができます。

どちらを使えばよいのかという話ですが、Bib$\LaTeX$ + Biber を選ぶのが無難かなと思います。 Biber は Unicode を前提に開発されているので、~~日本語文献の著者名やタイトルをわざわざローマ字に直す~~必要がないのは便利です。ただし、学会誌やジャーナルの投稿規定によっては bib$\TeX$ の使用せざるを得ない状況もあるかと思います。（Bib$\LaTeX$ を使わないという選択肢の下では Biber 単体では使えませんが、その際日本語文献の管理のために pBib$\TeX$ という選択肢もあります。）

[^stackexchange]: https://tex.stackexchange.com/questions/25701/bibtex-vs-biber-and-biblatex-vs-natbib

## 文書のコンパイル

### $\TeX$ ディストリビューションとコンパイルのためのコマンド

.tex ファイルをコンパイルするための実行バイナリや、関連パッケージ等、およそ $\TeX$ に関係しそうなものがひとまとめになったものを $\TeX$ ディストリビューションと呼びます。TeX Live とかがそうですね。

インストールすれば、コマンドラインで `platex` や `lualatex`、`biber` といったコマンドが利用可能になります。以前話題に上がった $\LaTeX$ エンジンに対応するコマンドもここに含まれます。例えば`platex main.tex` を実行すると、p$\TeX$ エンジンの上で、p$\LaTeX$ マクロパッケージのコマンドが展開されながら `main.tex` が解釈・処理されるでしょうし、`lualatex main.tex` なら Lua$\TeX$ エンジンの上で $\LaTeX$ マクロパッケージが用いられて文章のコンパイルが行われます。
